# ai_secretary

Мультиагентная система ИИ-секретаря кафедры. Обрабатывает входящую почту
(от студентов, преподавателей, администрации), классифицирует её и либо
отвечает автоматически, либо готовит черновик для проверки человеком.
Вся коммуникация идёт через почтовый ящик кафедрального секретаря по IMAP.
Написано с нуля на Python, без LangChain/LangGraph.

> Этот README описывает архитектуру и состояние проекта по итогам текущей
> фазы разработки перед защитой. см. раздел «Известные ограничения» внизу.

## Архитектура

```
main.py (единственная точка сборки приложения)
  ├─ MailConnectionManager  — единственная точка доступа к почте:
  │    сериализация конкурентных обращений + автопереподключение
  │    при обрыве IMAP-сессии
  ├─ poll_mail()             — читает INBOX, создаёт EmailReadTask
  ├─ sorting_agent.main()    — разбирает входящие письма/команды через
  │                            ReAct-агента (GigaChat), сохраняет черновик
  │                            ответа
  └─ sending_agent.main()    — выполняет рассылки индивидуальных заданий
                               руководителям практики студентов
```

### Компоненты

| Модуль                                |                                                                                                                                                                                            |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `utils/mailkit/mail_agent`                | Асинхронный IMAP-модуль: получение писем, сохранение черновиков, статус = папка                                              |
| `ai_secretary/mail_connection_manager.py` | Сериализация доступа к одному IMAP-соединению между тремя параллельными циклами + реконнект при обрыве |
| `ai_secretary/mail_poller.py`             | Периодически вычитывает INBOX, кладёт задачи в очередь sorting_agent                                                                             |
| `ai_secretary/ai_agent`                   | Каркас агента:`Model`/`Harness`/`ToolSet`/`ChatMemory`, ReAct-цикл, парсеры GigaChat/HuggingFace                                                            |
| `ai_secretary/agents/sorting_agent`       | Диспетчер: читает входящие письма, вызывает LLM+тулы, сохраняет черновик ответа                                            |
| `ai_secretary/agents/sending_agent`       | Рассылка напоминаний руководителям практики с приложением шаблона индивидуального задания                 |
| `ai_secretary/task_managers`              | `FileTaskManager` — общая очередь задач (JSON в папках-статусах на диске)                                                                        |

### Поток данных: входящее письмо -> ответ

1. `poll_mail()` вызывает `mail_agent.fetch_new_messages()`, для каждого
   письма создаёт `EmailReadTask` в очереди `FileTaskManager`, затем
   помечает письмо как `PROCESSED` (перемещается в IMAP-папку
   `Секретарь/Обработано`).
2. `sorting_agent.main()` в своём цикле забирает задачи со статусом
   `PENDING`, строит из письма `Message(role=USER, ...)` и отдаёт в
   `ReActHarness` — агент сам решает, нужно ли вызвать инструмент
   (например, `create_sending_task`) или просто сформулировать ответ.
3. Финальный ответ агента сохраняется как черновик через
   `mail_agent.save_draft()` (IMAP APPEND с флагом `\Draft`) — реальная
   отправка (SMTP) сознательно не реализована, ответ всегда идёт на
   проверку человеку.

### Поток данных: рассылка индивидуальных заданий

1. `create_sending_task` (тул sorting_agent) фильтрует студентов по
   Excel-базе (`faculty`/`degree`/`course`/`group`/`major`/`profile`) и
   создаёт `SendingTask` в очереди sending_agent.
2. `sending_agent.main()` для каждого студента: находит научного
   руководителя и его почту по базе, рендерит текст письма-напоминания
   из Jinja-шаблона, подбирает файл шаблона индивидуального задания по
   степени обучения студента (3-й лист Excel-базы), прикладывает его как
   есть (без автозаполнения полей) и сохраняет черновик через
   `mail_agent.save_new_draft()`.
3. Результат (успех/ошибка по каждому студенту) уходит отчётом обратно
   sorting_agent через отдельную очередь `agents_msgs`.

## Установка

Запускать **строго из корня репозитория** — `mail_agent` подключён как
editable-пакет через относительный путь, резолвящийся от текущей рабочей
директории:

```bash
pip install -r ai_secretary/requirements.txt
```

Это установит и `mailkit` (`utils/mailkit`, editable), и все прочие
зависимости, включая `transformers`/`torch` (нужны `ai_agent`, даже если
реально используется только GigaChat API — модуль `ai_agent.models`
безусловно импортирует `HuggingFaceModel`).

## Конфигурация

Скопировать `ai_secretary/.env.example` → `ai_secretary/.env` и заполнить
реальными значениями. Ключевые секции:

- `SECRETARY__*` — имя и почта секретаря для подписи в письмах
- `DATABASE__EXCEL_PATH` — путь к Excel-базе студентов/руководителей/шаблонов
- `DOCUMENTS__TEMPLATES_DIR` — папка с `.docx`-шаблонами индивидуальных заданий
- `SORTING_AGENT__GIGACHAT_AUTH_KEY` — ключ авторизации GigaChat API
- `MAIL__*` — креды IMAP-аккаунта секретаря (host/user/app-password),

## Запуск

```bash
python ai_secretary/main.py
```

Поднимает три параллельные корутины через `asyncio.TaskGroup`:
почтовый поллер, диспетчер (`sorting_agent`) и рассыльщик
(`sending_agent`) — все три делят одно IMAP-соединение через
`MailConnectionManager`.

## Известные ограничения

- **Нет OAuth2** — только `PasswordAuth` (app password). `OAuth2Auth`
  реализован как заготовка, не протестирован.
- **Нет IMAP IDLE** — новые письма подхватываются по таймеру
  (`poll_mail`, по умолчанию каждые 30 секунд), не мгновенно.
- **Реконнект — один retry, не полноценный backoff.** При повторном
  обрыве соединения сразу после реконнекта операция окончательно упадёт
  до следующего вызова.
- **Индивидуальные задания не автозаполняются.** Шаблон `.docx`
  прикладывается к письму как есть; ФИО и группу студента руководитель
  вписывает вручную.
- **Выбор шаблона задания — только по степени обучения** (лист 3
  Excel-базы, колонка `Степень` -> имя файла). Если появятся варианты
  под разные курсы/направления — потребуется расширение маппинга.
  Точное имя колонки с именем файла на 3-м листе нужно свериться с
  актуальной базой при интеграции.
- **`IMAPTaskManager`** (`task_managers/imap.py`) — альтернативная
  IMAP-based реализация очереди задач через голый `imaplib`,
  не используется нигде в приложении (используется `FileTaskManager`).
  Оставлена в кодовой базе, не поддерживается активно.

## Структура репозитория

```
ai_secretary/
├── main.py                      — точка входа, сборка зависимостей
├── config.py                    — pydantic-settings конфиг из .env
├── mail_connection_manager.py   — лок + реконнект вокруг ImapMailAgent
├── mail_poller.py               — периодический опрос INBOX
├── ai_agent/                    — каркас агента (Model/Harness/Tools)
├── agents/
│   ├── sorting_agent/           — диспетчер входящих писем
│   └── sending_agent/           — рассыльщик индивидуальных заданий
└── task_managers/                — очередь задач (файлы/IMAP)

utils/mailkit/
└── mail_agent/                  — асинхронный IMAP-модуль (editable-пакет)
```
